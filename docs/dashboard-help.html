Jahosi Mail receives email from Resend and forwards it to email addresses or application webhooks using recipient routing rules.

Overview

The overview shows message UUIDs, statuses, destination endpoint, and processing time. Message content details are never displayed in this panel.

Rules

To forward mail for apps@jahosi.co.uk, enter a rule name, set the pattern to apps with type Wildcard, choose Email address, and enter your destination inbox. Click Add rule and leave it enabled.

Save your Resend API key in Settings before forwarding to email addresses. Messages include their subject, plain text, HTML, and attachments. The sender display name shows a simplified original sender name followed by “via Jahosi Mail”, or “Jahosi Mail” when no name was supplied, using the gateway's configured sending address. Replies go to the original Reply-To address, or the original sender when none was specified. A forwarded-message header in the body also preserves the full original sender, recipient, date, subject, and reply address.

Create wildcard or regex rules that match the local part of recipient email addresses (e.g. pingme-(.*)).

The first enabled matching rule is used. Avoid overlapping rules and never forward back to the same receiving address. To change a destination, disable the old rule and create its replacement.

Use {ID} in destination URLs to inject the captured identifier.

Application webhook rules have their own key. Generate a secure key when creating a rule, then reveal/copy it from the rules table and validate it downstream via X-Jahosi-Webhook-Key.

Server log

Open Server log to view delivery attempts, UTC timestamps, and failure reasons. Click View log beside a message in Overview or Pending to see just that message. Refresh log fetches the latest results.

Pending also shows the latest stored error for existing failed messages. Earlier attempt details are available only for attempts recorded after this update. After correcting the error, click Retry; a failed retry updates the error and the log.

Login emails can arrive while forwarding fails: forwarding also needs access to Resend's received message content and attachments. The log identifies Resend API rejection or SMTP forwarding errors.

Pending Queue

Messages that fail delivery are retried up to five times every five minutes. Admins can manually Retry or Bounce.

Security

Login requires password + Cloudflare Turnstile + emailed OTP or magic link. In Settings, admins can update account email/password and manage webhook signing secret.

Troubleshooting Quick Guide

  • Check /readyz for gateway health.
  • Verify webhook secret in Settings if inbound calls are rejected.
  • If messages stay pending, validate downstream endpoint availability and response status.
  • For email forwarding, check that the Resend API key can read received emails and attachments, and that SMTP can send to your destination. Save a corrected key in Settings and use Retry in Pending.
